# 二期 P0.1 完成说明

在 P0 上新增 customers_get（company_id、id）与 ai_usage_ledger（company_id、可选 ISO day，默认上海当日）。工具参数严格校验并拒绝跨公司调用；HTTP 继续校验 x-agent-company-id 与登录 actor 公司一致。

客户详情 GET view=customer 复用 recordScope/assertScope 和 projectFields。AI GET view=ai-usage-ledger 仅管理员可读，按公司和日期汇总 risk_ai_runs 的状态、调用次数、预留美元微额；预留额度并非实际结算费用，不返回 prompt、receipt、result 或密钥。

Host 经共享只读 HTTP 客户端访问 view=agent-pipelines / agent-runs，业务查询通过 readBusiness 校验员工和公司，管理员权限，显式字段且每次最多100条。Host 不认领或执行任务，读取失败输出通用错误并继续心跳轮询。

## 本地调用

先启动应用并配置 AGENT_COMPANY_ID、AGENT_SESSION_COOKIE（管理员有效会话）及可选 AGENT_BUSINESS_ORIGIN（默认 http://127.0.0.1:3000），应用业务库需已应用 P0 migration。

运行 node scripts/agents/mcp-server.mjs，通过标准输入发送 JSON 行：

```json
{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"customers_get","arguments":{"company_id":"11111111-1111-4111-8111-111111111111","id":"22222222-2222-4222-8222-222222222222"}}}
{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"ai_usage_ledger","arguments":{"company_id":"11111111-1111-4111-8111-111111111111","day":"2026-11-04"}}}
```

替换示例公司和客户 UUID 为当前会话有权访问的真实记录。运行 node scripts/agents/agent-host.mjs 可每15秒查看心跳及真实 pipelines/runs。

未增加 SMTP、写工具、发信或任意 SQL 接口。未连接生产业务库进行验证。
