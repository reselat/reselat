# 二期 E2 完成说明

实现「草稿计划 → 人工确认 → 入队」闸门。仅采用简报所述 EvoFlow 先计划再执行的设计心智，未读取或复制其源码。

## 交付

- 新增 `agent_plans`：公司复合主键、pipeline 复合外键、RLS、仅 backend 授权；保存输入快照、可编辑步骤、版本号、确认管理员和时间。
- `plan_upsert` 可供业务 HTTP/MCP 创建和修订 draft；confirmed 计划不可再修改，变更需建立新计划。
- `plan_confirm` 只在同源已登录管理员 HTTP 路径提供；拒绝 Agent 标头，MCP 不列出且不能调用，通用编排命令也拒绝该命令。确认携带所查看的版本号，防止草稿被并发修改后发生盲确认。
- `run_enqueue` 严格要求 pipelineId + planId，从同公司同 pipeline 的 confirmed 计划复制输入，不接受外部覆盖 input。沿用业务命令幂等与审计。
- claim、advance、requeue、resume 均校验关联 confirmed plan 和输入一致性。历史无计划 run 保留可读和取消能力，但不能继续执行。
- 任务中心支持新建／修订草稿、展示快照和步骤、人工确认、确认后入队，run 列表展示 planId。计划确认不替代既有 outreach 人工审批。
- local-test 与独立本机迁移演练列表末尾加入 `20261105090000_agent_plans.sql`。

## 迁移与回滚

本次仅交付 SQL 文件，不执行远程迁移。上线前备份，先在隔离环境按既有顺序执行迁移，再部署配套代码。历史 run 不自动确认或补造计划，应由人工重新建立、审阅计划后新建 run。

回滚必须先停止 Host 和所有写入口，再回退配套应用；备份 plans 和 run 的 plan_id 关联后执行以下片段。回退会移除 E2 闸门，未重新评审前不得恢复旧 Host 执行。

```sql
begin;
alter table trade_business.agent_runs drop column plan_id;
drop table trade_business.agent_plans;
commit;
```
