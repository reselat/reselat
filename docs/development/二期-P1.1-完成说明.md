# 二期 P1.1 完成说明

实现人工批准/驳回审批队列。新增迁移 scripts/sql/20261104011000_human_approval.sql，部署时须先应用 P1 再应用本迁移；本次未连接生产数据库。

- POST /api/workspace/business 支持 outreach_approve、outreach_reject；input 为 {requestId, payload: {approvalId, human_actor_id}}。仅走既有管理员登录会话、同源校验及 MFA 检查，human_actor_id 必须等于会话 actor.id。带 x-agent-company-id 的审批请求拒绝。
- 默认 Agent write 的共享 schema 和 MCP 工具均不包含审批命令；普通 prospectCommand 也拒绝审批。Agent 服务身份没有新增审批入口。人工会话凭据须仍由人保管。
- pending 只能一次转为 approved 或 rejected；队列和草稿原子更新。驳回选用 rejected 终态，本期没有修改或重新提交 rejected 草稿的功能，后续需新建草稿。
- SQL 要求 pending 的 human_actor_id 为空，已决状态必须有人工 ID。
- GET ?view=approval-queue&state=pending|approved|rejected 支持过滤，省略 state 返回所有状态；返回 human_actor_id。
- 沿用公司隔离、公司事务锁、请求幂等和审计；审计包含 human_actor_id 与 draft_id。允许同一管理员在不同请求中提交及审批。
- 未加入 SMTP、outreach_send 或自动外发。

验证：npm test，93 个测试文件、328 项测试通过；npm run typecheck 通过。新增测试覆盖批准、驳回、草稿同步、人工 ID、重复请求及终态拒绝。原有用户修改及执行日志未纳入提交。
