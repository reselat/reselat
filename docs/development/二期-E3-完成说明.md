## MCP / Host 边界

MCP 进程用 `AGENT_ROLE_CODE` 选择当前岗位，默认 `prospecting`，岗位不能从工具参数切换。`tools/list` 读取公司当前配置，用该岗位提示词描述工具并移除停用或撤销的工具；只读 `agent_roles_list` 可查看配置。每次写入重新检查白名单，配置读取失败时不执行写入。

MCP 写工具收窄至当前岗位的业务动作，原有客户/跟进通用写入、审批后回写及编排设置写入不再暴露；计划、pipeline、入队仍可通过既有人工任务中心操作。`role_upsert` 不属于 MCP 工具，Agent HTTP 请求也不能修改角色。`plan_confirm`、`outreach_approve`、`outreach_reject`、`outreach_send`、`run_claim` 等均未加入 MCP 写工具列表。

Host 四步按 seq 使用获客、背调、邮件草稿、邮件草稿岗位，每步读取最新配置，携带 `x-agent-role-code`。后端检查 Agent 标记请求的动作范围，并对业务写入检查当前公司岗位；业务事务内再次校验，防止配置读取与提交之间被停用或撤权。Host 租约与推进命令保留为内部编排能力，没有进入 MCP。业务步骤 requestId 仍由 run ID + seq 固定派生，故障重放保持幂等，四步后仍为 `awaiting_approval`。

岗位越权返回 HTTP 403 `ROLE_ACTION_DENIED`。仍沿用既有管理员会话认证和 Agent 公司标记机制；本项没有引入独立 Agent 凭据系统。Host 继续执行既有确定性四步命令，没有新增模型调用。
