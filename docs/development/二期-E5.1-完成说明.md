# 二期 E5.1 完成说明

## 交付行为

任务中心 draft 计划提供「审阅并确认」入口。打开时保存审阅快照，展示计划 ID、版本、pipeline、name/email/subject/body/summary 和步骤说明，可就地编辑。原先分离的修订与直接确认入口合并为该流程；新建草稿仍使用原表单。

- 无改动：使用打开面板时的 version 调用 `plan_confirm(expectedVersion)`。
- 有改动：先调用 `plan_upsert`，仍保存为 draft；读取返回的 version 后再调用 `plan_confirm`，不依赖列表异步刷新取得版本。
- `plan_upsert` 增加可选 expectedVersion，用于人工审阅编辑的 CAS；返回 `{id, version}`。未传版本的既有调用保持兼容，confirmed 计划依然不可修改。
- 过期编辑、保存与确认之间发生并发修订时均拒绝；失败后停止流程并要求重新审阅。网络结果不确定时保留原请求，可核对结果，不自动重新保存或确认。
- 审阅提交期间阻止重复提交及切换审阅计划。列表仅在 confirmed 时展示入队按钮，服务端未确认计划仍拒绝入队。

## 实现范围与约束

仅自行实现当前 React UI 和必要的现有 upsert 返回值/CAS 扩展。只阅读 EvoFlow README 中可审阅计划、人工介入的设计理念，没有读取或复制实现，没有 side-car、vendoring 或新增依赖。

复用现有会话管理员入口、公司隔离、命令幂等和审计。`plan_confirm` 仍只由会话 HTTP 分支调用，不进入 orchestration/MCP dispatch。MCP 禁区保持：plan_confirm、run_claim、pipeline_advance、run_resume、outreach_approve、outreach_reject、outreach_send。Agent 无自批能力；未增加 SMTP、nodemailer 或发送行为，编排仍停于 awaiting_approval。

未读取生产 .env、未连接远程/生产数据库、未部署 Host/Vercel、未启动监听服务。数据库验证使用测试内存 PGlite。纯文案和样式微调留 E5.4；DAG、技能扩容、真实 Postgres 均未涉及。
