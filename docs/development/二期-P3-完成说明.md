# 二期 P3 编排 MVP

追加迁移 `20261104013000_agent_orchestration.sql`，须在 foundation、prospecting、human approval、writeback 后执行。固定模板 `prospecting_semi`：线索、尽调、邮件草稿、提交审批。无摘要时记录“未提供尽调摘要；需人工核查”。agent_steps 使用公司与 run 复合外键、RLS 和 backend 授权；租约默认五分钟。

业务 POST `/api/workspace/business` 使用 `{action,input:{requestId,payload}}`。新增 pipeline_upsert（id/name/enabled）、run_enqueue（pipelineId/input）、run_claim（id/owner）、pipeline_advance（id/owner/seq/evidence:{id}）、run_cancel、run_requeue、run_resume（后三者 payload 为 id）。全部复用管理员权限、公司隔离、业务事务、审计和请求幂等。advance 校验租约、顺序和本公司业务证据。claim 直接 queued→running，reserved 为预留状态；冲突报 LEASE_CONFLICT。

Host：设置 AGENT_COMPANY_ID、AGENT_BUSINESS_ORIGIN、AGENT_SESSION_COOKIE 后运行 `node scripts/agents/agent-host.mjs`。使用业务 HTTP 接口，无直连 SQL。AGENT_INTERVAL_MS 默认 15000，串行循环。每个 run/seq 使用固定请求 ID，命令成功而 advance 失败时可安全重放。失败日志不含密钥或业务内容。

急停：AGENT_STOP=1（启动时读取）或创建默认 `.agent-stop` 文件（AGENT_STOP_FILE 可指定路径）停止下一步；run_cancel 取消指定运行并清空租约。已开始的 HTTP 命令可能完成，取消后 advance 将拒绝。超时 running/reserved 或 failed 由定时调用 run_requeue 回收，Host 下一轮领取；不自动重试未知错误。不得在 Vercel 运行常驻 Host。

提交审批后释放租约并停在 awaiting_approval。人工批准及写回沿用现有会话闸门；完成写回后显式 run_resume 才标 succeeded。禁止 SMTP、发送命令和 Agent 自批。MCP 新增 pipelines_list/runs_list/run_get 与 pipeline_upsert/run_enqueue/run_cancel；不暴露 claim/advance/resume 或审批操作。多渠道适配器留待后续，仅允许合规输入快照。
