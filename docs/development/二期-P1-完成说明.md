## 使用

先按既有数据库迁移流程应用上述 SQL。MCP 继续使用 AGENT_BUSINESS_ORIGIN、AGENT_COMPANY_ID、AGENT_SESSION_COOKIE，由操作员提供有效管理员会话。

POST 结构为 {"action":"命令名","input":{"requestId":"UUID","payload":{...}}}；MCP 参数为 company_id、requestId、payload。

1. leads_upsert：name、email、source（manual/json，默认 manual）。人工粘贴或 JSON 逐条导入；邮件转小写，公司内按 email 去重，返回 id。
2. diligence_save_report：leadId、summary。保存人工整理的背调摘要，不抓取或自动调用模型。
3. outreach_draft_email：leadId、subject、body。保存人工提供的邮件草稿，状态 draft。
4. outreach_submit_approval：draftId。草稿改为 pending，创建唯一审批项并记录 submitted_by；重复提交不增加队列项。

上述 id 返回供下一步引用。所有命令均记录审计，无 SMTP、outreach_send、自动发送、定时任务或自动编排。

## 人工审批边界

本期仅入队，无批准/拒绝操作。队列 state 数据库约束只能 pending；human_actor_id 本期必须为空。未来审批功能必须在独立人工会话入口记录人工 actor，并校验禁止自批，不能把 Agent 提交会话视为人工审批证明。本期 Agent 无任何批准入口。
