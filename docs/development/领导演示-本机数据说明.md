## 5. Brevo 真发要配的 env

产品侧读**服务端**环境变量（与 Cursor Brevo MCP token **不是**同一个）：

```bash
# 写入本机 shell 后再启动 test:local；勿提交真实密钥
export BREVO_API_KEY='…'              # Brevo → SMTP & API → 普通 API key
export BREVO_SENDER_EMAIL='wanjiesale@gmail.com'
export BREVO_SENDER_NAME='万捷演示'   # 可选，默认 Trade outreach
npm run test:local
```

`.env.example` 已补 `BREVO_*` 占位。`start-local-test.mjs` **不会**剥离 `BREVO_*`，但也不会自动加载 `.env`；需 export 或自行用 dotenv 工具注入。  
缺 key 时按钮会提示「请配置服务端 BREVO_API_KEY 与 BREVO_SENDER_EMAIL」，适合演示失败回退。

**默认演示不要真发。** 真发前务必把线索邮箱换成你能收的地址，并确认发件域在 Brevo 已验证。

## 6. 失败回退

| 现象 | 处理 |
|------|------|
| 3120 打不开 | 重新 `npm run test:local`；确认无其它进程占端口 |
| `MIGRATION_REQUIRED` | 重启 test:local 让 local-test 增量迁移跑完；仍失败再备份后删 `.local-test-data` 重建 |
| 获客页空白 / 非管理员 | 退出后用「测试管理员」重登 |
| Brevo `BREVO_CONFIG_REQUIRED` | 未配 key：口头说明人点发通道已接、密钥后置即可 |
| 误点发送到测试邮箱 | example.test 收不到；到 Brevo 活动日志核对即可 |
| 想重新预置 | `node scripts/seed-leadership-demo.mjs` |
