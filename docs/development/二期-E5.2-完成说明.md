## 实现

- 自研 `scripts/agents/step-graph.mjs`：严格声明 `step_key / seq / role_code / action / depends_on`，检查唯一 key/seq/action、同图引用、重复依赖、无环、岗位动作白名单。只支持现有四种业务动作各一次，不扩容技能。
- 默认线性图：`prospect → diligence → outreach_draft → outreach_submit`。可声明分支依赖；尽调和草稿必须有线索祖先，提交审批必须汇合所有业务步骤。按 seq 对就绪节点稳定排序，每次串行执行一个节点；seq 是声明标识，不再等同已完成数量。
- 新迁移 `20261105120000_agent_step_deps.sql`：pipeline 图、run 图快照、步骤 key/role、公司/run/key 唯一索引；回填旧四步记录，可重放。沿用原 RLS 与权限，无新表、无客户端授权、无 CASCADE。接入 local-test 新建/存量库与 rehearsal。
- `pipeline_upsert.payload.stepsGraph` 可选；不传时新建默认图，更新时保留已有图。入队从同公司启用 pipeline 冻结图快照，后续 pipeline 编辑不影响该 run。
- Host 按快照找下一个依赖全部 succeeded 的节点，加载声明岗位技能并检查岗位权限。业务 requestId 继续由 run ID + 声明 seq 确定，保留补跑幂等；业务写入及 advance 前再次检查急停。
- `pipeline_advance` 在原事务锁、人工确认、租约、公司条件内验证 seq/key/依赖/稳定就绪顺序，复查当前岗位权限；按 action 查找与前置线索/草稿关联的证据，记录岗位交接。未就绪与非法图返回明确业务冲突。提交审批后仍停在 `awaiting_approval` 并释放租约。
- 任务详情只读展示全部声明的步骤 key、岗位、依赖、状态；Plan 文案仅说明，结构化图为执行依据。时间线按实际记录时间展示，避免重排 seq 后顺序和间隔错误。未做页面样式改造。
