# E5.2 实施计划

以任务简报为规格；本次直接执行用户已授权的实现与提交。

采用 pipeline.steps_graph + run.steps_graph 快照，共用自研校验与就绪选择器。相比单独步骤表，无新表权限和跨行校验复杂度；相比解析 Plan 文案，结构化图可严格验证。仅支持已有四类业务动作，各一次；允许依赖分支，串行执行就绪节点。seq 是声明标识，非完成数量；终节点必须依赖所有业务步骤。Plan 文案仅说明。

1. 先写图校验/就绪、编排拒绝测试并观察失败；实现共享声明、角色白名单、无环与依赖校验。
2. 新增可重放迁移：pipeline 默认图、run 快照、步骤 key/role；接入新建与存量本地库及 rehearsal。编排快照与按 action 校验证据，保留事务锁、租约、人工确认与公司条件。
3. Host 从图选择就绪步骤，按声明岗位执行；最小只读 UI 展示声明与完成/就绪/阻塞状态。
4. 跑 Vitest 全套、typecheck，检查 MCP 禁区与发送路径；独立审查，完成说明，只提交本任务文件。

验证重点：非法图、未知/重复 key、环、错误岗位/动作、跳步/未满足依赖、错误 seq/key、run 快照冻结、禁用岗位、崩溃重放、人工闸门。
