# 思链台开发总结与维护手册

本文件描述代码的实际情况。早期v1.0方案是设计历史，不是当前安装指引。配套通用模板见《通用业务系统开发与交付模板》，下一阶段候选方案见《思链台本地化与二期扩展方案》。

## 1. 产品与现状

思链台用于外贸团队主档维护、订单履约、单据及业务收付款协作。当前正式入口为 `/workspace`，登录 `/login`，成员管理 `/admin`。`/demo`重定向到workspace，登录页不再推荐旧本机试用区。旧UI源文件保留为历史测试资料；部分领域schema被正式模块复用，暂不贸然删除整个旧目录。旧浏览器localStorage不会自动迁入共享库。

已实现客户/产品/供应商、合同与开票资料、样品/正常订单、采购和到货、出运装箱、销售/采购收付款与冲销、PI/PO/CI/PL/SC、受控签章、CO证书关联下载、退税资料准备、分币种余额、管理员审计与成员停用。退税准备不等于自动申报，收付款台账不等于会计总账，签章图片不等于电子签约。

云端验收站仍为Vercel+双Supabase，包含经用户要求保留的SYNTHETIC验收资料。不得把客户演示或真实生产交付与此环境混为一谈。本轮本地化为开发底座和候选部署文件；没有客户服务器，尚未完成真实局域网、公网及离线断网验收。

| 范围 | 实际实现 | 维护入口 |
|---|---|---|
| 应用 | Next.js 16.4.2、React 19.3.1、TypeScript | src/app、next.config.ts |
| 数据库 | PostgreSQL、postgres.js 3.4.9，参数化SQL | src/server/db、src/server/business |
| 表单/校验 | 原生form/FormData、React、Zod 4.6.7 | src/modules/business/ui |

## 3. 模块边界

`src/app`负责路由、身份入口和HTTP；`src/modules/business`负责界面、DTO与输入契约；`src/server/business`负责事务、权限和业务命令；`src/server/documents`、`files`、`refunds`分别负责归档、对象和资料包；`src/domain`负责不依赖网络的金额数量规则。`src/modules/workspace/model.ts`等旧路径仍提供共享schema，不代表正式业务使用localStorage。

这是模块化单体，适合目前的团队规模。模块边界清楚，但不是每个模块独立部署的微服务；共享schema位置和部分较长TSX仍有技术债。维护时围绕边界分批改，不在一次需求中重写全站。

## 4. 数据与权限

身份库保存公司成员、角色、停用、成员审计与Auth会话；业务库保存主档、订单、采购、到货、出运、收付款、单据、文件元数据和业务审计。应用用独立identity_backend/business_backend角色，不以超级用户运行。

角色只有admin/sales/operations。管理员敏感操作要求aal2；销售仅授权客户/订单和销售字段；运营按分配订单处理采购履约。全局及订单操作记录仅管理员可读。我方公司资料在财务菜单，客户合同/开票资料在客户管理。菜单隐藏不能代替服务端鉴权。

数据库用途标记同时核对purpose和project_ref，防止身份/业务连接串接反。自建配置必须显式DEPLOYMENT_TARGET=self-hosted、各自数据库host及用途角色；云部署默认保持原有域名与TLS校验。

## 5. 业务流程与不变量

主档 → 草稿订单 → 提交/确认 → 采购确认 → 到货 → 分配来源数量 → 出运草稿/确认 → 单据归档及收付款 → 退税资料准备。

- 待确认只计submitted；confirmed与fulfilling计正在履约。
- 没到货来源不能出运；CBM必须正数，厘米尺寸换算提供辅助，不替代实际装箱核验。
- 订单/单据使用冻结快照；主档修改不覆盖历史合同及发票。
- 金额整数和数量十进制经过字符串JSON传输，不用JavaScript浮点数计算财务金额。
- 命令requestId+载荷摘要防重放，版本字段防旧页面覆盖；公司锁串行化关键变更，吞吐需实际压测后评估。
- 冲销/作废追加历史；CO文件通过产品/供应商及订单引用授权下载。
- 上传最终回读校验大小和SHA256后才标记stored；uploading只是历史步骤，异常结果需要核对，禁止盲目覆盖。

## 6. 维护操作表

| 需求 | 修改位置 | 必做验证 |
|---|---|---|
| 字段新增 | schema→DTO→权限字段投影→表单→快照/模板 | 三角色可见性、旧记录兼容 |
| 状态流程变更 | 服务端命令/锁/约束→界面 | 旧版本、重复提交、越权、数量边界 |
| PDF修改 | templates与冻结文档数据 | 文本、字体、实际PDF排版 |
| 数据库变更 | 新追加迁移，保留已应用SQL | PGlite、低权限查询、备份恢复演练 |
| 文件适配变更 | BusinessStorage接口 | 不覆盖、摘要、来源鉴权、异常恢复 |
| 部署配置 | deployment、db/config、deploy/local | 云配置拒绝降级、自建用途隔离、重启持久化 |

安装 `npm ci --ignore-scripts`；开发 `npm run dev`，访问 `/login`。提交前运行 `npm test -- --maxWorkers=2`、`npm run lint`、`npm run build`、`npm run typecheck`。CI在push/PR时执行同一检查，并另构建self-hosted standalone。CI成功不等于浏览器全流程、真实网络并发或灾备恢复已通过。

## 7. 文档治理

优先级：当前README/本手册和实际代码 → 当前部署runbook → 决策记录ADR → 历史方案/证据。设计与实现不同时，PR必须说明原因、更新本手册和测试；用真实依赖与验证证据修订文档，不用旧文档反推代码必须如此。

每个版本记录：需求、非目标、架构决定、迁移影响、测试结果、未验收项、部署ID、回滚方式。历史证据保留并标注日期，不持续重写成“当前状态”。

## 8. 交付与备份

GitHub私有仓库备份代码、锁文件、迁移及无密钥文档。`.env*`、会话、私有附件、数据库备份、.vercel和构建产物不得推送。代码异地备份不包含数据库或Storage数据，也不代替客户资料灾备。

客户交付要有独立数据环境、初始管理员/MFA、备份路径和恢复演练、更新责任人、模板确认、局域网与互联网验收清单。测试数据当前明确保留，演示清理另经确认；严禁把假资料改名伪装成真实资料。

## 9. 已知边界与后续

本地Auth栈安装/数据库新装与迁移工具、首管理员引导、容器真实运行、运行监控、备份恢复、双入口网络验收仍是本地交付工作，候选Compose并不是一键产品。财务与AI目前仅版本化契约/接口，无自动外发，无已接通声明。当前不实现离线浏览器副本、双机自动同步、多租户SaaS或自动会计入账。
