# 二期 P2 完成说明

已实现批准后显式半自动写回。推荐顺序为 outreach_submit_approval → 人工会话 outreach_approve → outreach_writeback。审批事务只改变审批状态；写回独立运行，失败可重试。不包含 SMTP、发送适配器或 outreach_send；MCP 不暴露 approve/reject/send。

## 业务与事务

outreach_writeback 输入为 {requestId, payload:{approvalId}}，要求管理员 aal2，queue 与 draft 均 approved。通过 runBusinessCommand 按公司锁串行化，requestId 原样重放返回相同结果，更换 requestId 重复写同一 draft 拒绝。客户保存、跟进、lead/draft/queue 标记和 audit 同事务提交，失败全部回滚。复用 saveRecordInTransaction / addFollowupInTransaction；原有 saveRecord / addFollowup wrapper 保持不变，VERSION_CONFLICT 沿用原版本检查与错误响应。

按本公司客户 payload.email 小写匹配；多个匹配时按 created_at/id 选择首项。已有客户不修改编码、owner 或阶段。新客保留首录审计和系统编码分配，阶段 potential，来源 other，地址待补，其余联系字段空串。跟进日期使用 Asia/Shanghai，nextDate 默认 +7 天（WRITEBACK_NEXT_DAYS）。note 含 [AI辅助] 前缀、已批主题与最新背调摘要，长文本分别截取以符合 2000 字上限。

## MCP 与统计

新增 customers_save_draft → record.save(customer)、followup_add → followup.add，以及 outreach_writeback。所有参数经严格 Zod 校验并校验 company_id；沿用 x-agent-company-id。customers_save_draft 不接受 customerCode，阶段只允许 potential；更新要求 expectedVersion，由业务层处理冲突。

customer-development、MCP customer_development_stats 和开发统计 UI 新增 aiFollowups，按业务日期、actor 与 note 的 [AI辅助] 前缀计数；它是原 followups 总数的子集，原人工统计口径不变。此前缀是统计约定，不是机器执行来源的不可伪造证明。
