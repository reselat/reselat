# 二期 P0 完成说明

采用独立 Node 脚本，复用根目录 Zod，不引入 monorepo 或 Vercel 长驻任务。MCP 是 stdio JSON-RPC 服务，仅调用现有业务 GET；不持有数据库、Auth Admin 或模型密钥，不实现 SMTP、写工具、阶段变更或真实编排。

## 工具及权限

| 工具 | business view |
| --- | --- |
| customers_list | records，固定 kind=customer |
| followups_list | followups，id 为客户 UUID |
| customer_development_stats | customer-development |
| customer_stage_suggest | customer-stage-suggestion |
| company_get | company |
| orders_list | orders |
| orders_get | order |

所有工具要求 company_id UUID，使用 strict Zod 校验；列表接受 offset/search，详情接受 id，统计接受可选 day。作用域必须匹配宿主配置；受控请求携带 x-agent-company-id，业务 API 再与登录员工 companyId 比较，拒绝会话错配。原有员工启用状态、角色、字段投影及记录 ACL 继续由业务函数校验。会话失效不绕过鉴权。异常返回固定文本，不输出上游错误或凭证。

customers_get 暂缺：现有 GET 没有客户详情能力，不能用分页列表伪造详情。ai_usage_ledger 暂缺：现有用量查询用于预算计算，没有独立只读公开能力；P0 不新增 SQL 查询或暴露模型设置。两项均未注册，后续先补 business 只读能力再包装。

## 本地验收

先 npm ci --ignore-scripts；npm run dev，使用合成公司账号登录。仅在本机环境中设置 AGENT_COMPANY_ID 为该员工公司 UUID，AGENT_SESSION_COOKIE 为该登录会话的 Cookie 请求头值。不要提交或在日志输出 Cookie。不要将数据库 URL 或管理密钥传给脚本。

启动：node scripts/agents/mcp-server.mjs。默认连接 http://127.0.0.1:3000；可用 AGENT_BUSINESS_ORIGIN 设置可信 HTTPS 应用源。仅使用当前操作员授权会话，不提供独立服务账号鉴权。

向标准输入依次写入以下单行 JSON（替换公司 UUID）：

```json
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"local","version":"1"}}}
{"jsonrpc":"2.0","method":"notifications/initialized"}
{"jsonrpc":"2.0","id":2,"method":"tools/list"}
{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"customers_list","arguments":{"company_id":"11111111-1111-4111-8111-111111111111"}}}
```

无真实会话时可运行 npx vitest run tests/agent-foundation.test.ts，使用合成 UUID 与内存 read 夹具验证工具列表、映射、参数校验和跨公司拒绝。

宿主：配置 AGENT_COMPANY_ID 后运行 node scripts/agents/agent-host.mjs；立即及每 15 秒输出 idle 心跳与空 pipelines/runs，Ctrl+C 停止。心跳不持久化，列表明确为内存 stub，没有任务领取、执行或恢复。host.mjs 留出 Orchestrator 扩展点。
