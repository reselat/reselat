# 设置中心与财务退税预审入口

## 问题与改动

原财务“退税资料”仅展示业务列表，AI操作藏在订单详情，不符合用户从财务办理退税的路径。现在/workspace/refunds直接选择有权访问的订单，复用原资料整理、人工复核、CSV/PDF/ZIP导出与AI资料包面板。PI、CI、合同生成流程不变；订单原有退税页保留同一组件。

操作：财务管理 → 退税资料 → 选择订单 → 整理并导出资料包 → AI退税预审 → AI预审本版本。模型关闭时明确显示未启用并禁用执行按钮，不显示通过。业务员可看所属资料，导出及预审仍由管理员／该订单运营负责人办理。

设置菜单统一放置设置中心、个人资料与账号安全；管理员另有员工资料与角色、离职交接、AI模型设置、上传维护、业务操作记录。/workspace/settings仍为我方公司资料，继续归财务，避免改旧链接含义。所有员工可维护本人资料和外观；服务器在每次管理员读取和写入时复核身份、状态和AAL2，不靠隐藏菜单授权。

## AI设置

/workspace/ai-settings：显示服务端开关、密钥是否存在、每日费用和次数上限。支持保存公司偏好：模型、公司开关、费用／次数限额、订单风险与退税清单两类业务开关。不开启真实AI，不试调用，不新增供应商或依赖。

新增trade_business.ai_application_settings，仅一公司一行、版本号及无密钥JSON偏好。管理员命令沿用公司行锁、幂等、版本冲突与审计。业务数据库与身份库分离不变。SQL由固定Supabase CLI 2.122.0 migration new生成后放入本仓库scripts/sql，加入full-business迁移序列；本地新装也按同一顺序执行。

实际执行先检查服务端DEEPSEEK_RISK_ENABLED和原密钥／核价约束，再检查公司开关与任务开关，限额取公司与服务端较小值，两个任务共用原预算台账。新增设置不会提高平台上限。激活模型须与服务端核价模型相同，避免切换贵模型后沿用旧单价。设置保存不上传密钥、不改Vercel环境、不发送模型请求。无偏好行时沿用已有环境配置以兼容旧版本；当前环境false/0，因此无实际调用。

API：GET view=ai-settings、POST ai.settings.save仅管理员；GET view=ai-availability只返回可用布尔及安全错误码。没有密钥回显、任意端点或网页密钥存储。

迁移：scripts/sql/20261027095948_ai_application_settings.sql，仅追加私有表、RLS及business_backend精确权限，不改身份库、不删除历史、不付费。无DELETE授权；anon/authenticated无权限。平台私有schema不暴露Data API，后端仍显式按company_id筛选。回退应用保留新表。
