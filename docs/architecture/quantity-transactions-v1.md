# 数量事务与后续集成测试规格

状态：未执行真实 PostgreSQL 集成。本轮只有十进制解析与余量校验纯函数。

## applyPurchaseAllocation

输入：actor、companyId、salesLineId、supplierId、quantityDecimal、expectedVersion、idempotencyKey。

在同一连接事务中：核验可信员工和资源 → 锁定销售父行 FOR UPDATE → 查幂等记录并比较请求摘要 → 重算有效采购与草稿预留 → 验证需求余量 → 创建采购行／预留 → 更新表头 version → 写审计和幂等结果 → 提交。

所有采购入口锁同一销售父行，不能只锁当前已有采购记录。多个父行按 ID 排序锁定。不得以 SDK 多次请求或本机互斥锁代替事务。

## reserveShipment

输入：actor、shipmentId、expectedVersion、sources[{receiptLineId,quantityDecimal}]、idempotencyKey。

先按固定顺序锁销售行、采购／到货来源和出运表头，事务内核验来源同公司同销售行；重算验收量－已消耗－其他有效预留；写预留、版本、审计和幂等结果。确认出运把预留转消耗，不再次扣量。作废草稿释放预留。

## 异常和逆向

- 减少上游数量不得低于有效下游量。
- 到货错误仅在无下游占用时冲回，保留原流水。
- 取消采购只取消尚未履行量，不删除到货。
- 已实际出运不能通过删出运恢复余量，实物退货另立业务。
