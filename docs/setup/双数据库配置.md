# 双数据库安全配置

旧configure-database.mjs单库向导已停用。两个独立测试项目已初始化并完成连接配置；以下步骤用于受控配置与恢复，不应重复初始化已配置角色。不要把身份项目地址填作业务连接。Vercel 环境配置见 [Supabase与Vercel部署.md](./Supabase与Vercel部署.md)。

## 1. 身份库

保留现有登录邮箱/密码及MFA；迁移创建identity_backend并写入身份用途标记后，在本机终端运行：

```sh
node "/Volumes/数据/开发项目/外贸工作站/scripts/configure-separated-databases.mjs" --purpose identity --project-ref qgbsikqgunmsipegkvda
```

按隐藏提示输入该项目Connect的Session pooler URI（5432，保留[YOUR-PASSWORD]），下一步输入数据库密码。脚本只存新identity_backend低权限连接，不存postgres连接。TLS始终验证，默认使用随项目保存的公开Supabase根CA，可用--ca指定受信任公开CA文件。

## 2. 业务库

取得实际新业务项目ref、完成业务库迁移后运行同一脚本：--purpose business --project-ref 后填实际新ref。不得使用身份项目ref；不在命令参数中传连接串或密码。此阶段依赖身份项目ref已保存在本机配置，防止两库同项目。

两次配置各自生成专用角色密码和独立连接；一次完成不代表两库全部完成。身份库可独立用于成员管理，业务库未就绪时业务API拒绝，不回退旧TRADE_DATABASE_URL。

## 3. 员工创建服务

在本机运行configure-auth-admin.mjs，隐藏输入身份项目Secret key；不使用业务项目key、publishable key或数据库密码。该脚本只配置，不创建员工或发邮件。它检查本机IDENTITY_PROJECT_REF和浏览器登录URL指向既有身份项目。

配置完成重启本项目开发服务。成员管理员登录仍用原Auth账号/MFA，不需重新绑定验证器。

## 只读检查和失败恢复

在对应--purpose和--project-ref参数后附加：

- --check-only：隐藏输入管理员URI/密码，只查认证、用途和角色状态；不改角色或本机配置。
- --verify-saved：只用本机已保存的该用途低权限连接验证角色/用途，不打印连接，不改密码。
- --recover-config：只在该用途.setup.tmp仍存在时使用；读取本机临时低权限连接，实际认证和用途校验通过才合并该用途三项配置，保留其他用途及密钥；不重置角色密码。认证不通过则原样保留，不假报成功。

角色事务明确被拒绝（如42501/42P18）时清理本次创建、确定未提交的临时文件；提交结果未知则不删。不要把“无完成提示”当成“服务端未执行”。恢复失败时只反馈用途、阶段、安全错误码，不发连接串、密码、原始错误或配置文件。

.config.lock用于避免两个配置进程覆盖.env；两个用途和Auth key配置共用锁。进程被强制结束可能残留锁；先确认没有配置进程仍运行，再由维护者检查锁与临时文件，不自动删除或绕过锁。维护者介入前可以继续只读诊断，不反复初始化角色。

配置文件/临时凭据文件位于已忽略的.env.local*路径，权限0600；不进入Git、文档或聊天。旧TRADE_DATABASE_URL暂保留在本机时也不会被运行时代码使用，后续撤销旧角色及移除旧配置另行审核。
