# 管理员首次连接配置

适用：独立测试项目 trade-workstation-test（qgbsikqgunmsipegkvda），不是其他数据库。

首位管理员已关联且账号邮箱确认状态通过；连接凭据尚未配置，仍不能进入共享业务后台。

## 在本机终端执行

```sh
cd '/Volumes/数据/开发项目/外贸工作站'
node scripts/configure-database.mjs
```

1. 打开该Supabase项目的Connect面板，选择Session pooler，复制URI形式的postgres数据库管理员连接串。使用Session pooler避免本机不支持IPv6导致直连失败。使用5432端口、postgres数据库；若URI末尾附带问号查询参数（如sslmode），请去掉问号及后面的参数，脚本自身强制验证TLS，禁止连接参数覆盖账号或项目。
2. 保留URI里的 `[YOUR-PASSWORD]` 占位符，不需要手动把密码拼进URI。脚本会在下一步单独隐藏询问数据库密码，并自动编码特殊字符。数据库密码不是员工登录密码；若不知道，可在这个独立测试项目的数据库设置中自行重设，不要改其他项目。
3. 在第一个隐藏提示中粘贴带占位符的URI并回车，在第二个隐藏提示中输入实际数据库密码并回车。两次输入均不回显。不要把连接串、密码、密钥发送到聊天、截图或代码文件。
4. 脚本校验项目和低权限角色状态，随机设置专用app_backend连接密码，只保存专用连接至被忽略的.env.local，权限0600；不保存管理员连接、不发送邮件、不导入业务资料。
5. 成功后重启开发服务，打开 http://127.0.0.1:3000/login ，用你刚创建的员工账号登录。进入双重验证，按页面绑定验证器，输入一次性验证码后进入管理员后台。

若提示已配置或无法验证，请停止，不要重复初始化或把凭据发到聊天。可以只报告不含凭据的提示文字。脚本当前未完成真实凭据联调，不能据语法或本地单测声称配置必成功。

不要公开验证器二维码或一次性验证码。员工邀请和密码重置邮件仍未开启，不会自动外发。

## 安全诊断

新版只输出固定阶段和白名单错误码，不输出原始错误、主机、连接串或密码。例如 `connect / 28P01` 表示数据库密码认证失败；`SELF_SIGNED_CERT_IN_CHAIN` 表示证书信任问题；`configure_role / 42501` 表示角色配置权限不足；`parse` 阶段提示连接串格式或参数不合要求。未知错误不直接打印服务端正文。只反馈这行脱敏诊断即可。

## TLS证书（已修复SELF_SIGNED_CERT_IN_CHAIN）

配置脚本和应用现在默认加载项目内 assets/certificates/supabase-prod-ca-2021.crt，无需手动下载。证书从官方Studio配置指向的HTTPS地址取得，指纹与来源记录于同目录README。

已使用本机Node与实际Session pooler做无凭据STARTTLS探针，证书链和主机名验证通过；不代表数据库密码或低权限角色已验证。重新运行原配置命令即可。

如平台以后轮换证书，可从项目Database Settings的SSL Configuration下载公开CA，并使用 `--ca "/绝对路径/证书.crt"` 指定；脚本仅接受有效CA证书、不接受私钥，仍保留rejectUnauthorized及主机名验证。成功配置后证书路径会写入.env.local供应用使用。

## 28P01重复出现时

先停止反复重置密码。可运行只读检查，不启用角色、不改数据库密码、不写.env.local：

```sh
node '/Volumes/数据/开发项目/外贸工作站/scripts/configure-database.mjs' --check-only
```

连接串请从当前trade-workstation-test项目Connect中原样重新复制（保留密码占位符），不要手工拼接pooler主机；第二步单独输入数据库密码。

脚本已修复raw终端粘贴的ESC[200~/ESC[201~控制序列污染，支持分段控制序列和Unicode退格；拒绝多行粘贴，不输出密码。若显示已过滤终端粘贴控制符，可据此确认输入经过清理，但不能据此认定此前28P01就是它造成。

只反馈目标项目、主机及诊断码或成功提示；不要提供密码或完整带密码URI。项目直连在当前环境TCP可达但TLS探针超时，暂不推荐切换直连。

## 成员管理更新：创建员工账号

成员管理迁移必须先经审核应用；它新增归档状态、创建追踪和有限业务写权限，不删除旧数据。

管理员页面右上角“添加成员”创建员工账号；填写姓名、邮箱、至少12字符初始密码、角色。无自动邮件。初始密码由管理员通过公司认可的方式交给员工，不应粘贴到聊天或文档。

创建服务还需要项目服务端secret key（项目设置中的API Keys；可使用Secret key，或本项目旧版service_role）。数据库密码和publishable key不能代替。只在本机终端运行：

```sh
node "/Volumes/数据/开发项目/外贸工作站/scripts/configure-auth-admin.mjs"
```

在隐藏输入提示处粘贴，不回显；不在命令参数中粘贴。脚本仅写本机忽略配置，权限0600，不发邮件、不创建账号；保存后重启开发服务。新式secret key的项目归属会由固定项目端点认证，不靠名称推测；脚本格式检查不代表远端认证成功。

成员编辑可改姓名/角色；停用会限制所有新的平台请求。移除采用归档，保留客户和历史记录；在“已归档”筛选中恢复，恢复后默认停用。最后一位启用管理员不能被降级、停用或移除。

创建中断请打开“待处理创建”，可翻页查看早期请求。已记录Auth UID的请求可“恢复员工关联”；未知结果须核对Auth账号并填写其User UID，系统会核对服务端创建请求标记。不要凭猜测重试创建或填写别人的UID。确定被拒绝的创建须检查邮箱/密码后重新发起。
