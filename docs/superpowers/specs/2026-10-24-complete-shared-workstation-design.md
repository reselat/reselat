# 完整共享外贸工作台：设计与验收范围

状态：用户已确认完整共享实现书面设计，包括运营指派采购/出运权限扩展。保持此前Native实施选择。对应逐项实施计划待审核，不把设计确认当成尚不存在计划的批准。

## 1. 目标与既有事实

单公司，自营采购出口B2B，先收客户订单再采购。一次登录进入统一工作台，管理员与业务模块共用账号；身份项目和业务项目保持独立。

当前已完成：身份/MFA/成员增改归档、两库独立连接；客户/产品基础共享API；原demo本机订单、采购、出运、收付款、PI/PO/CI/PL/SC模板及HS/退税索引。当前未完成：这些业务模块的共享事务、完整角色闭环、归属移交、私有文件、签名使用和退税完整资料包。用户报告员工创建已成功；不以此替代其他业务验收。

目标闭环：管理员配置公司/员工/产品/供应商 → 业务员录入客户与跟进 → 销售订单 → 确认 → 按供应商采购 → 到货/分批出运 → 合同及PI/PO/CI/PL → 收付款和欠款 → 退税资料检查/附件归档/打包。所有本期模块完成后才交付“完整系统测试版”，每个模块不能用“稍后开发”或假成功代替。

沿用用户此前约束：无finance角色，不开发会计总账、凭证核算、自动报税；实现订单业务收付款和外部财务API契约/关闭的outbox。默认受控签名图片，不引入付费电子签约服务。

## 2. 统一界面与业务入口

统一/workspace主导航：工作台、客户与跟进、销售订单、采购、出运、产品/HS编码、供应商、业务收付款、单据中心、退税资料、公司设置。管理员另有“公司管理”，进入既有成员/角色/审计工作台，可返回业务区。菜单及接口都执行权限检查，非管理员直访/admin仍拒绝。

沿用已确认浅色办公视觉、完整宽度、清晰表格和侧边编辑面板；桌面与窄屏均可操作。默认自动加载、分页/搜索/筛选、加载/无数据/错误重试、保存防重复、版本冲突提示、确认动作明确。数据服务不可用显示错误，不回退localStorage。

订单详情为核心：概览/商品与HS/采购到货/出运装箱/单据合同/收付款/附件退税/操作记录。订单阶段、待办、负责人及欠款一目了然，点击提醒直达对应记录。

原/demo保留为隔离的本机历史试用区，标明不共享；正式登录工作台没有以demo代替模块的链接，不自动读取/上传原localStorage。是否导入旧本机资料为后续独立审批动作。

## 3. 身份与业务权限（本轮需审核扩展）

角色仍为admin/sales/operations。以下是拟实施权限，运营不再仅限当前共享基础资料只读：

| 能力 | 管理员 | 业务员 | 运营 |
|---|---|---|---|
| 成员/角色/公司收款信息 | 全部管理，MFA | 无 | 无 |
| 客户/跟进 | 全公司维护、分配、共享、移交 | 本人客户维护，显式共享客户只读 | 分配到订单所需客户资料只读 |
| 产品与HS资料 | 维护并复核 | 查看销售资料，不见默认成本/供应商 | 维护产品及HS草稿；管理员复核；默认采购成本不开放 |
| 销售订单 | 全部管理/确认 | 本人订单建草稿、编辑、提交；已确认变更受控 | 指派订单查看与履约；不可更改销售价格 |
| 供应商/采购/到货 | 全部管理 | 不见采购成本与供应商资料 | 指派订单所需供应商资料与采购成本可见，可建采购草稿、录到货；管理员确认采购 |
| 出运、CI/PL | 全部管理/确认 | 本人订单查看、预览 | 指派订单录入出运/装箱、提交确认 |
| 收付款 | 登记/确认/冲销 | 本人订单提交收款登记，查看销售应收状态 | 指派订单采购付款状态只读；不见公司银行完整信息 |
| 正式单据/签名 | 确认和授权；可显式授权具体运营使用特定签名 | 查看本人订单已确认客户侧单据，不见PO或签名原图 | 指派订单制作和提交；正式确认/签名使用须有明确授权 |
| 附件/退税 | 全部整理/复核/下载 | 本人订单非采购敏感文件，上传客户侧凭证 | 指派订单整理/补件/打包，按文件敏感类别过滤 |

所有范围company_id及owner/assignment/share由服务端查询；不信客户端role。数据库金额/采购字段在DTO、导出、PDF及附件处同时过滤，不能只隐藏按钮。管理员敏感API保留AAL2和有效会话核验。

客户共享默认只读。管理员分配/移交前查询身份库确认目标员工同公司且有效；单客户负责人及共享版本受控更新。移交提供明确预览：客户、跟进、未完结订单及履约指派；默认同步移交客户关联的未完结订单，保留created_by等历史身份。已完结订单不暗中更换负责人，必要时显式授予新负责人只读访问。撤销共享/移交后旧负责人下一次请求拒绝；跨库已通过鉴权的在途操作仍可能完成，不承诺跨库原子撤回。

## 4. 共享业务功能

### 4.1 主档与跟进

公司商业抬头、地址、银行资料只在业务库；身份库公司表仅为身份目录。客户保留来源（既有Finder式色点）、联系人、跟进时间线、下次跟进和负责人。供应商独立维护。产品保留中英文名称、规格、单位、原产国、销售价与采购默认值、HS编码、申报要素、退税商品代码/税率人工核验依据和复核状态。

选客户、产品后带入订单草稿，金额由后端重算；订单确认时冻结公司、客户、商品及归类信息，修改主档不回写历史订单。HS不自动推断归类；未复核或字段缺失在报关/退税准备中明确拦截，不伪装成合规凭证。

### 4.2 销售订单与采购

草稿→待确认→已确认→履约中→完成；取消保留记录/原因。未确认可按版本编辑；已确认修改生成变更版本，已产生采购/出运/收付款时执行约束检查，不覆盖正式历史。

业务员建单不要求输入成本和供应商。确认后管理员/指派运营在采购工作台从销售行生成采购，可按供应商/币种拆分，可分多张采购单；采购量累计不得超过对应销售行可采购数量。采购草稿→待确认→已确认→部分/全部到货；到货明细引用采购行，累计不得超过采购数量。不开发独立库存、调拨或仓储系统。

### 4.3 出运

出运明细显式关联销售行及已到货采购来源，保证对应销售行累计出运≤确认销售量、每来源分配≤已到货且未分配量。同一商品多采购来源可拆分。取消草稿不占正式量，取消已确认出运需反向释放分配并保留审计，不直接删明细；已有正式CI/PL则先明确作废关联并保留原件。

箱数、净重、毛重、体积、唛头、尺寸、港口和运输方式可维护；毛重不得小于净重，正数与单位一致。支持同订单分批出运；CI/PL来自实际批次，不用整单数量代替。分批金额保留确定的累计舍入规则，最后批次可对账到订单。

### 4.4 业务收付款与首页

业务员可提交本人销售订单收款登记；管理员确认后才计入已收。采购付款由管理员登记/确认。状态为待确认/有效/已冲销；冲销必须有原因，不删除流水。付款币种须与关联订单/采购单一致；多币种分别汇总，不把汇率换算估值混成已结算金额。

首页展示未收订单、未收金额、逾期、待采购/待出运、缺件及下次跟进；按角色范围计算，管理员可看采购应付。金额按最小单位整数存储和计算，数量/单价4位定点；金额字段使用可精确转换的整数串，服务端限制数据库精度范围（金额NUMERIC(38,0)，数量/单价NUMERIC(24,4)），拒绝超范围，不以浮点处理余额。

外部财务仅交付明确API字段/鉴权/幂等与对账说明及默认关闭outbox，不自动发送数据到第三方，不呈现未实现的连接成功状态。

## 5. 合同、单据、文件与签名

### 5.1 文档

PI、PO、CI、PL及正式销售合同SC：来源业务记录→草稿预览→有权限者确认→不可变快照与文件。草稿带明显草稿标识；合同生成、图像盖章、上传客户签署件分别标记，不把生成当签署成功。可编辑合同条款（质量/包装/运输/检验/保险/违约/不可抗力/争议/生效及补充）并冻结至每个合同版本。

沿用React-PDF及本机固定字体，升级来源快照和排版完整性，不复制客户端提交的金额为正式数据。下载API只接受受权documentId，不接受任意JSON伪造正式单据。版次、模板版本、来源版本、生成者、确认者、摘要及SHA256可追溯；作废/更正生成新版本，旧PDF保留。

持久化生成意图/状态/幂等键；渲染→私有上传→记录文件hash和完成状态。重复请求取同版结果，不重复授权盖章。跨数据库/Storage无原子事务，渲染或上传异常有重试与核对状态，不能把未知上传结果当未发生。正式PDF读取固定文件字节，不随主档或签名更换而重渲染。

### 5.2 私有文件

文件放业务项目私有Storage桶，业务库只存元数据/关联/hash；需要该业务项目单独的仅服务端Storage管理密钥（用户本机隐藏输入），不能复用身份项目secret或放浏览器。后端先核验身份和文件所属对象权限，再代理上传/下载，默认不把可转发签名URL给浏览器；签名原图无普通员工下载入口。

桶和后端均限制类型/大小。首版附件PDF/PNG/JPEG，每文件≤10MiB；签名/印章PNG/JPEG≤2MiB。检查扩展名/MIME/文件头、随机对象路径、实际大小和SHA256；文件名只用于显示，下载强制attachment并nosniff。拒绝SVG/HTML/可执行文件；不承诺完成病毒扫描或真伪鉴定。上传意图、对象成功和关联确认分状态，失败不标已归档，不覆盖已有正式PDF路径。

### 5.3 受控签名图片

管理员上传、命名、停用签名/印章，授权具体有效员工及用途；单据确认时再次显式选择与确认，绑定单据快照版本并记使用记录。停用阻止新使用，不改变已生成文件。签名原图不公开、不进入日志/源码/测试/普通API；现有PNG/JPEG内容只用于既定模板位置。

页面使用“签名/印章图片”“已加盖图片”等准确状态，不宣称专业可靠电子签约。专业CA签约/在线客户签署、付费平台对接不在本轮。

## 6. 退税资料完整整理

按订单关联采购/出运/单据/收付款/外部上传凭证，默认沿用现有7类清单，管理员可维护适用性与复核意见。missing/uploaded/pending_review/reviewed/not_applicable状态分明；无实际文件不能仅用“有存放位置”标已归档；不适用项必须原因及管理员确认。

展示缺件和可机械检查的不一致（合同/CI/PL来源、数量/金额/币种、HS及核验依据），不自动判断退税资格。报关单、提单、供应商发票仅作为外部取得凭证上传，系统不伪造它们。

可下载CSV目录、资料检查PDF、以及ZIP资料包（目录/检查表/有权限的PDF和附件，附文件摘要清单）。打包先核验整个请求及每个文件，默认总原始文件量≤50MiB、最多100文件；超限明确提示缩小范围，不漏文件假报完整。缺件时可下载标明缺件的草稿资料包，不显示“资料齐全”。

ZIP可将现已安装的间接依赖fflate 0.8.3（MIT）提升为固定直接依赖，但需在实施计划展示许可证/锁文件变化并获依赖授权；不从未声明的间接依赖直接导入。

## 7. 持久化、并发与备份

业务库追加按业务实体拆分的orders/order_lines、purchase_orders/purchase_lines/receipts、shipments/shipment_lines/allocations、payments、documents/versions/jobs、attachments/links、signature_assets/grants/usages、refund_checklists/reviews及followups等表；复用已有主档/共享关系/业务审计，不能上传整个Workspace JSON覆盖多人资料。跨库仅稳定UUID，不建员工角色镜像或跨库外键。

每次读取/写入带company_id与服务端scope。业务写、数量预留/分配/释放、版本条件与业务审计同业务库事务；公司内编号用数据库序列/受锁计数，不用数组长度或浏览器生成正式编号。确认/收付款/出运/资料包生成使用幂等键，重复键不同载荷拒绝。多会话旧版本不能覆盖新值，禁止重复确认/超采购/超到货/超发货/超收付款。

身份库变更与业务事务无跨库原子性，仍按现有分库设计实时身份核验，失败拒绝，不放宽为客户端鉴权。Storage跨服务失败单独记录可恢复状态，不对真实数据自动删除“补偿”。

联合备份范围为业务数据库、私有文件与关联/hash清单；身份配置与身份审计另行备份，不在普通业务导出包中包含Auth密码hash/secret。提供用虚构资料的隔离恢复演练，验证关联/摘要/文件可用性；真实数据导出、云端恢复和历史清理另行授权。

## 8. 完整测试版验收

1. 同一入口登录，管理员可切业务/公司管理，业务员无管理权限；刷新和另一浏览器访问数据一致。
2. 管理员设置虚构公司、供应商、产品/HS，业务员录客户来源/跟进并建订单；负责人/只读共享/同步移交生效，越权直访API拒绝。
3. 管理员确认订单；按供应商采购并确认到货；运营仅在指派范围内履约，业务员看不到采购成本。
4. 两批出运、跨采购来源分配和并发超量测试通过；状态/余额/待办与明细一致。
5. 生成PI/PO/SC及每批CI/PL；PDF长品名、中英文、多页、页码/重复表头、金额、箱重体积核对；旧版不随主档修改而变化。
6. 上传虚构印章授权、单据级确认使用、撤销新使用权限；未授权及原图下载拒绝；已生成文件不变。
7. 收款/付款登记确认、部分结算、逾期、重复流水、超额和冲销测试通过；按币种计算首页欠款。
8. 上传虚构外部凭证、复核退税清单，缺件和不适用状态清晰，CSV/PDF/ZIP可下载并核对内部文件摘要；越权附件不能混入包。
9. 失败场景：双人旧版本、重复请求、权限撤销、身份库故障、PDF/Storage中断恢复；没有假成功和静默localStorage回退。
10. 保留现有153测试基线并新增有意义回归，完整测试/lint/build/typecheck与独立只读复核；本地双库集成、虚构浏览器交互和用户获批的云端测试分别记录，不用mock冒充真实验收。
11. 交付逐步测试脚本、角色测试清单、虚构测试数据准备入口（显式触发，不自动初始化真实库）、已知限制和恢复说明；全部本期模块接通后再邀请用户测试完整闭环。
