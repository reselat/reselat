# RESELAT 二期首阶段：企业私有部署与夜间业务助手设计草案

日期：2026-10-31。状态：用户于2026-11-01确认设计并同意继续编制实施计划；尚未执行产品开发、付费调用、微信自动收发或云端变更。

作者与版权所有者：朱春茂。

需求来源：[二期调研汇总](../../architecture/2026-10-31-RESELAT二期调研汇总与启动清单.md)。本文把首阶段收窄为可验证的助手试点；Meta／Google投流、完整课程系统和30企业集中管理另列后续子项目。

## 1. 目的与已确认需求

完整版RESELAT未来服务30家缺乏外贸经验的工厂；你既负责培训，也带业务员跑业务、谈客户和投流。每家企业可在自己的服务器独立部署，讲师及运营团队通过临时授权参与业务。

首期消息渠道为微信和邮箱。个人微信用作测试载体，Bot读取企业选定的客户会话；非工作时间自动接待，工作时间由业务员接管。DSH Bot为优先运行方案。允许自动回复产品资料、审核FAQ、需求收集，以及企业已有的统一PDF报价单；其他业务问题交人工。

用户已选择PDF自动提取、人工审核后发布。每家企业的报价独立；统一报价不代表忽略规格、数量、币种、有效期或贸易条件，也不授权模型自行定价。

## 2. 方案取舍与范围

### 已讨论的替代方案

| 选择 | 取舍与决定 |
|---|---|
| 共用多租户实例／每企私有部署 | 用户选择企业服务器独立部署；保留同一产品代码，不复制成30份各自演化的业务实现 |
| 点击读取／指定会话持续监听 | 夜间自动接待目标需要持续监听；仅限授权会话，工作时间人工主导 |
| 直接依赖模型读取PDF／提取审核后发布／人工录入 | 前者不能作为精确价格依据；用户选择提取后人工审核，人工更正作为必要补救 |
| 业务代码内运行Bot／独立运行DSH并适配 | 助手提出后者供本设计审阅：保持业务服务与Bot生命周期分离，用受控接口通信 |

### 首阶段包含

- 企业实例隔离要求与本机虚构试点；企业知识和报价资料的导入、审核、发布、撤销。
- 原始消息、客户关联、人工／Bot接待状态、需求摘要、回复及引用记录。
- DSH版本与接口探针、个人微信指定会话只读／发送探针；能力不足时明确阻断。
- 受预算约束的助手任务、接管竞争、重复消息、异常回执和只读审计验证。
- 邮箱通道契约与可测试的模拟通道；真实邮箱选型及OAuth连接作为独立小交付，服务商未确认前不宣称接通。
- 临时辅导授权的业务规则与独立验收任务，不能以当前管理员会话代替服务团队身份。

### 后续独立交付

Meta优先、Google其次的投流方案和看板；完整课程／练习平台；30家企业的集中服务目录、授权汇总及版本管理；正式服务器安装、升级、异机恢复；外部财务适配。这些沿用二期目标，不混入首个微信技术探针。

首阶段不承诺30企生产承载、真实邮箱上线、个人微信全历史同步或稳定自动收发。任何技术探针都不替代正式上线验收。

## 3. 当前代码与部署边界

基线为 `/Volumes/数据/开发项目/外贸工作站` 的完整版，调取时HEAD `ceb923b`。已有Next.js、postgres.js、身份／业务双库、私有文件、MFA、确定性业务命令、审计、多模型加密配置、预算及未知结果核对。

当前身份服务按固定 `TRADE_COMPANY_ID` 识别公司，适合首先复用每企独立实例；没有已完成的跨企业服务授权系统。现有AI任务仅连接测试、订单风险、退税预审，不能直接当通用Bot任务账本。

工作台／API、身份服务及身份库、业务数据库与文件、DSH运行环境分别划定权限。企业之间不共享DSH_HOME、会话目录、工作目录或数据库凭据。可先同服务器分服务试点，实例隔离不等于不同故障域；正式部署另做备份恢复和资源验证。

Bot只使用受控工具，不持有原始DB管理连接、微信密钥、主加密密钥或讲师长期会话。个人微信需本机采集端，服务器不能自行获得员工桌面会话。DSH内部接口由适配器包装，固定试验所用提交／版本，不把内部通道当稳定第三方API。

## 4. 产品资料与PDF报价的发布

资料有导入、待审核、已发布、已撤销状态；原件保留摘要、来源、版本、上传人和时间。模型或OCR输出一律为待审核候选。

报价流程：上传PDF → 文件校验 → 文本提取或OCR候选 → 人工逐项核对／更正 → 预览价格和条件 → 发布。无法解析、乱码、跨页错行、多个币种或条件不明确时不自动发布。尚无PDF样本，扫描识别质量和具体提取引擎必须在探针中验证。

发布报价条目包含企业、产品及规格、价格、币种、计价单位、PDF页码、原文定位和版本；数量适用条件、贸易条件、有效期等来自原件并经人工确认，原件未说明时允许显式“未指定”，不能填充模型猜测。条件未指定且影响客户当前报价时，转人工。

单价沿用现有精确十进制处理，禁止JS浮点算钱。报价匹配使用确定性字段和适用条件；语义检索仅帮助找到候选产品，不能选择最终价格。对原报价未覆盖的汇率、折扣、运费、税费或数量阶梯不自行计算。客户询问总额时，首阶段只引用原单价与条件，金额计算交人工。

PDF原件、结构化条目和回复引用绑定同一发布版本；发布新版本不改写既往回复证据，旧版本可撤销。发送前重新检查版本有效性及适用性。附件发送由渠道能力单独验证，不因文本回复可用就默认附件可发。

## 5. 原始聊天、知识和记忆

原始消息保存外部来源、企业／实例、渠道账号、稳定会话映射、消息ID或可核验指纹、方向、发生时间、接收时间、正文及附件引用；客户原话与AI摘要分开。人工校正客户关联需要留痕，不允许模型改变企业归属。

首阶段只处理文本。图片、语音和未识别附件记录为需人工处理，不假装理解；产品PDF仅走已审核知识与报价流程。历史范围只包含实际采集／获授权导入的记录，界面或结果必须说明覆盖范围。

公开课程、企业私有资料、客户原始会话、Bot摘要和偏好分别管理。检索前校验范围；不能先将全部企业内容送给模型再过滤输出。DSH团队记忆不得跨企业复用。价格、交期等事实引用发布记录，不能仅凭记忆回答。

## 6. 自动接待规则

企业配置时区、营业时间、工作日和例外日；未配置或冲突时只生成草稿，不自动发送。首阶段不写死上下班时间。

会话有 `human`、`bot`、`waiting_human` 状态。是否允许Bot自动接待还取决于会话授权、工作日历、渠道健康、已发布知识、预算和暂停开关。

- 工作时间进入human，AI可提供草稿，不自动发送。
- 非工作时间且前置条件全部满足时进入bot。
- 业务员可随时接管；任何人工接管立即停止后续自动发送，尚未发送结果保留为草稿／已取消记录。
- 需人工核实的问题进入waiting_human。仅可发送企业事先批准的接待／转人工提示，不作其他业务回答；没有批准模板时只记录待办。
- 手动接管不会因为到达夜间再次自动解除；恢复Bot需要业务员或企业有权人员明确操作。

自动回复白名单：发布的产品资料、FAQ、需求收集、适用的统一报价单。禁止自行议价／调价、承诺交期、给出付款指示、修改合同、修改订单、审批财务或执行广告操作。识别不了意图或资料不足时转人工。

需求收集阶段可询问产品、规格、数量、用途、目的地等，但不以收集到信息为由自动修改已确认订单或生成正式单据。对外身份说明和转人工模板发布前由企业确认；无模板不启用真实自动发送。

上班交接提供客户需求、夜间已发回复、引用资料版本、未解决事项和建议下一步；保留原文入口。人工与Bot所有发送都纳入同一会话记录，不能让业务员重复处理而看不到Bot已答内容。

## 7. 发送的一致性与异常

消息重复回调或重复采集按企业＋账号＋会话＋来源消息标识去重；同一会话串行处理，顺序不明先等待／转人工。持久化处理状态后才产生外发，不能靠进程内变量防重复。

一次回复准备、发送尝试、渠道回执分别记录。发送前重新核验企业、会话映射、授权、接待状态、人工接管版本、时段、报价版本、预算和渠道健康。接管与外发必须通过同一确定性协调机制；仅有“发送前读一次”不能消除并发竞争。个人微信界面操作发生中已触发的发送无法承诺追回，界面须区分已发与已停止。

外发超时或缺少可核验回执进入unknown，禁止自动重发，先核对原尝试，避免客户收到重复报价。断线、客户窗口变化、账号变化或会话识别不确定时暂停采集／发送并在工作台记录异常。重连后先重新校验身份与会话，不把积压消息整批补发。

这些要求是进入真实自动接待的门槛。如果个人微信渠道无法提供足够的去重、接管和回执证据，只保留只读／草稿试验，不能默默降低标准后称完成自动接待。

## 8. 模型、预算与DSH工具

首阶段默认模拟模型和测试资料，外部调用预算0，不读取或复制现有真实Key。真实模型试验必须另行确认数据范围及费用上限；现有1美元／日上限不会自然覆盖DSH的独立调用。

DSH只可通过受控服务查询已授权知识、客户上下文、报价匹配和保存草稿。自动消息发送交给确定性接待服务，Bot不能直接操作发送工具或取得SMTP／微信收发凭据。

技术探针必须列明DSH主回复、记忆、压缩、后台处理和其他模型请求的路径，证明均受计费与限制约束；做不到时不提供真实模型密钥。每个企业独立限额、并发、暂停与调用记录；渠道动作不由模型结果自行扩权。

报价、客户消息和PDF都是不可信输入，其中的指令不能改变工具权限、读取范围、收款账户或预算。模型返回必须结构校验，包含回复类型、文本、来源及待人工事项；价格字段必须与当前匹配记录一致。

## 9. 临时辅导授权

企业有权管理员批准指定外部辅导人员、访问范围、可执行动作和有效期。建议默认只读，业务写入逐项明确。讲师或Bot不能批准自己的申请或自动续期。

访问与每次工具执行在企业实例核验；到期、撤销或成员停用后拒绝后续请求和发送。进行中的任务取消／降为不可发送草稿。MFA与原业务审批继续适用，临时授权不等于管理员权限。

授权时长由企业选择，本设计不替用户设置统一时长。身份验证和临时成员开通方案在该子项目实施计划中确定，不使用公共管理员账号或共享固定token。企业可查看申请、批准、访问、变更、到期和撤销记录；原始聊天正文与密钥不进普通操作日志。

此授权用于人工辅导；企业自己的Bot服务身份和模型外发许可独立管理。企业可先不开通外部辅导功能而使用本企业工作台，不能令日常经营依赖讲师在线。

## 10. 里程碑与验收

| 阶段 | 交付与通过标准 |
|---|---|
| E0 技术探针 | 固定DSH／DS Bot候选及许可；测试一个虚构微信会话的识别、读取、回复／回执、接管与断线；验证PDF文本／扫描识别差异和DSH全调用路径；列出通过／未通过能力，无真实客户外发 |
| E1 资料与报价 | 原件、候选抽取、人工更正与审核、版本发布／撤销；用人工核对的虚构样表验证价格、单位、币种、条件及页码；未审核资料无法用于自动报价 |
| E2 接待服务 | 在模拟渠道实现夜间／工作日历、人工接管、需求摘要、白名单和发送账本；重复、超时、重启、撤销、过期报价与注入测试通过 |
| E3 DSH与通道适配 | 通过受控工具接待；个人微信只启用E0证实可行的能力，不能收发则显式降级；邮箱先模拟，真实服务商另选；实际接入无会话串线及未授权调用 |
| E4 独立企业试点 | 在隔离实例验证完整流程、备份恢复、临时授权和访问撤销；随后单独批准真实渠道与模型范围，再逐家扩大 |

首阶段不承诺工期；技术探针先回答个人微信是否能可靠实现目标。正式开发拆成独立计划：E0探针、资料报价、接待任务、DSH／渠道适配、临时授权、私有化交付。技术不成立的分支回到设计，不用演示成功替代验收。

## 11. 留给实施者的选择

具体PDF提取／OCR工具、任务持久化的最小实现、适配器内部组织、测试夹具和部署脚本细节，按现有技术栈及E0证据提出，新增依赖与上游版本在实施计划中固定。日志保留、备份目标、正式模型预算、邮箱服务商、具体工作时间和对外模板在各企业启用时显式配置，未配置时保持对应能力关闭。

本文中“建议”及未由用户逐项给出的默认行为，均为设计提案，需在文档审阅中确认。它不是对微信接入、第三方平台许可、服务器容量或自动销售效果的保证。
