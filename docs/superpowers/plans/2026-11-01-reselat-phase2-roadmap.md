# RESELAT 二期首阶段交付顺序

作者与版权所有者：朱春茂。日期：2026-11-01。

设计依据：[已确认设计](../specs/2026-10-31-reselat-phase2-assistant-pilot-design.md)。本文件是交付依赖图，不是后续子系统的详细实施计划。

## 执行顺序

| 顺序 | 独立交付 | 输入／输出及验收门槛 |
|---|---|---|
| E0 | [技术验证详细计划](2026-11-01-reselat-assistant-e0-plan.md) | 固定DSH候选、模型路径、微信能力、PDF样例证据；输出逐项supported/unsupported/unverified，不以模拟结果冒充真实验证 |
| E1 | 资料与报价发布 | 根据E0确定提取器，独立设计主档关联、审核权限、私有原件、精确金额、发布撤销；输出可追溯版本，未审核条目不可报价 |
| E2 | 接待服务与模拟通道 | 根据E0契约独立设计持久任务与发送记录；证明日历、去重、接管串行化、未知结果核对及资料撤销生效 |
| E3 | DSH／实际通道适配 | 仅启用E0证实能力，调用E1受控检索、E2接待服务；模型不得持有渠道密钥或直接外发；邮件服务商确定后另列真实连接计划 |
| E4a | 临时辅导授权 | 单独明确外部人员身份、授权范围、企业审批、过期与撤销；在企业实例验收，不能复用共享管理员身份 |
| E4b | 私有化试点交付 | 同产品代码、独立配置／身份库／业务库／文件／DSH目录；安装升级、备份与异机恢复实测后才扩大企业数 |

E1、E2详细计划在E0证据确定后编制；它们不是已经完成设计的数据库迁移。E4a可单独规划，不需要提前购买服务器。Meta／Google投流、培训课程、30企集中服务目录仍属后续子项目。

## 基线与变更控制

- 完整RESELAT为基线，保留既有财务、风险和多模型功能；万捷新材料副本不变。
- 当前阶段只保存文档，不推送触发部署，不接触原云库与真实Key。
- 开发在隔离分支／工作区进行；不带入遗留未跟踪的scripts/audit-facts.sh或任何.env文件。
- 每个子交付单独测试、评审、提交；实际迁移和上线前提交可审阅的变更与回退方案。
- 验收报告必须分清模拟、真实本机试验、真实企业环境三个证据层级。

## 本轮自检

设计第1—3节对应整体基线和交付分离；第4节对应E0 PDF能力及E1；第5—7节对应E0消息契约及E2/E3；第8节对应E0调用路径及E3；第9节对应E4a；第10—11节对应本顺序与各子项目计划。当前详细计划只覆盖E0，其他项目不能按本表直接开始产品实现。
