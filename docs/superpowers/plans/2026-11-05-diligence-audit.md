# M-AI1 背调互审实施计划

**Goal** 实现简报定义的闸门 A、确定性融合与人工例外处理。

**Architecture** 独立 JSON 互审记录保留生成稿、审计席、证据与融合结果。沿用业务事务、公司锁、幂等和审计，HTTP 区分 Host 管道命令与人工决定。

**Spec** `docs/development/二期-M-AI1-任务简报.md`

## 约束

路径 A，仅背调。模型不具有人审权。测试使用 fixture，无密钥。禁止发信、Maps、开发信自动批准。保留工作区既有文件。

## 实施与验证

- [x] 写融合与数据库回归测试并观察失败，覆盖来源优先、两家一致、单家推断、分歧、无来源敏感声明、阈值、重复席位与缺席。
- [x] 新增 `src/modules/business/diligence-fusion.ts`，提供严格结构、纯融合函数及可注入席位接口。
- [x] 新增 `scripts/sql/20261105130000_diligence_audits.sql` 和 `src/server/business/diligence-audits.ts`，提供提交、记审、融合、人工确认/驳回、列表。验证公司隔离、事务、重试与终态。
- [x] 接入 workspace HTTP 和获客背调 UI，保持 MCP 白名单边界，接入本地数据库迁移。
- [x] 运行 Vitest 与 typecheck，审查 diff，记录完成说明并精确暂存提交。

## Review Focus

空稿和空审计不能自动接受。来源引用必须指向已存证据。审计席不能重名增加票数。融合和人工处理不能重复生成报告。跨公司 ID 不得读写。

## 实施选择

一致率按每项声明的支持席位数除以总席位数，取最低值。有任何分歧、敏感无来源声明或审计阻断均进入人工。人工确认单独记录决定和操作者，保留初始融合状态与依据。来源代表调用方提交的可追溯证据，系统不抓取 URL。
